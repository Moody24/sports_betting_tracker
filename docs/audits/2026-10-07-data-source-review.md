## Quota and webhook implications

The Odds API documents REST polling. Its `/events` endpoint has no credit charge but still requires a key; it supplies listed pre-match/in-play events, not an established full-season schedule contract. `/scores` updates approximately every 30 seconds and can return completed games for only the previous three days; cost is one credit, or two with `daysFrom`. Odds cost depends on markets and regions. Market-level `last_update` stops advancing when a market closes/suspends, with removal after about 15 minutes. [V4 documentation](https://the-odds-api.com/liveapi/guides/v4/)

Calculated budget example: three markets × one region × one request/minute × six live hours × 30 days = **32,400 credits/month**, before scores and event-specific props. The 500-credit free tier cannot sustain that workload. At three credits per poll it permits about 166 such polls/month. Internal caching avoids duplicate consumers but cannot remove the cost of collecting new observations.

BALLDONTLIE explicitly documents signed provider webhooks; none is configured or authorized for this app yet. Free limits cannot cover every league start/end over a full month. A receiver would verify the signature over timestamp and raw body, bound timestamp age and deduplicate the delivery ID, then reconcile authoritative state. The baseline now adds a durable Games snapshot and 100-event journal to a single scheduled BALLDONTLIE poller. Browsers share authenticated SSE delivery with JSON fallback; this is internal event delivery, not provider push. The separate ESPN polling coordinator retains its existing final-game workflows. For an admitted source, use **permitted polling → normalized persisted change → internal event/outbox → cache/UI update**. Do not label a local event bus, polling adapter, browser SSE stream, or scheduled task as an upstream provider webhook. Before enabling any verified provider push, review its authentication, permission, replay and ordering guarantees.

## App-specific findings and implementation direction

Read-only inspection covered `README.md`, `app/services/espn_client.py`, `nba_service.py`, `api_budget.py`, `hoopr_import_service.py`, `release_data_service.py`, `app/cli/prop_odds_import.py`, and the canonical `docs/architecture/system-contract.md`.

- README calls ESPN “free, no auth.” Replace this with a statement about technical access and unresolved permission; do not imply a license.
- `espn_client.py` currently issues direct requests; release importers also depend on ESPN-derived data. A provider review must cover both live and bulk paths.
- `nba_service.py` uses advisory 60-second game and 300-second upcoming-game caches. Those TTLs do not demonstrate source latency. Preserve provider update time separately from successful fetch time.
- Retain `APIBudgetManager` when using the existing authorized odds integration. A provider-neutral ingestion layer should preserve provider/event/market identifiers, source timestamp, observation timestamp, data version, rights basis, and retry state. Never silently substitute IDs from another provider.
- Recommendations for the next implementation: one centrally governed poller per permitted source; shared durable observations; idempotent normalization; internal change events; bounded retries honoring rate limits; stale/unavailable states; no implied fresh data after a failed fetch. These are proposed engineering directions, not changes made by this review, and must follow the canonical system contract.

## Remaining blockers

1. **Permitted scores and player-stat feed:** ESPN and NBA-hosted data cannot currently be admitted on the evidence found. Existing historical releases also need a documented source-rights chain.
2. **Live odds without credentials/payment:** no reviewed source meets all constraints. An existing authorized Odds API key may support a deliberately limited collection plan; sustained live coverage requires a sufficient existing entitlement or a later user decision.
3. **Invited beta rights:** record permission for actual display, retention, derived outputs, ML use, and downstream access before admitting each source. Prevent raw-feed exports where forbidden.
4. **Coverage verification:** TheSportsDB's 2026–27 NBA season endpoint could not be validated in this execution environment: the web fetch returned an internal error, and the local read-only probe failed DNS resolution. This is an environment limitation, not proof the provider is down. Complete the coverage check before adoption; never bypass the documented free-tier cap.

No accounts, subscriptions, messages to providers, purchases or live scheduler runs were made. The launch implementation adds separate admission gates for ESPN-derived and NBA Stats network reads, while preserving licensed local-file imports. This document records source-admission evidence and blockers; it does not claim the application is cleared for beta.
